# Release 0.9.8: patch, with two review findings accepted

- Date: 2026-10-01
- Status: accepted
- Scope: the release review of `0.9.7..` (MOB-226, MOB-311, MOB-310, MOB-49,
  MOB-237, MOB-315/316/178)

## Context

The release review gate (`RELEASE.md`) read the accumulated diff since 0.9.7.
It recommended 0.10.0 instead of a patch and flagged one iOS regression. A
third finding (mob_new's generated `{:mob, ...}` floor must require this
release before the notification templates ship) is handled in mob_new's
release and is not recorded here.

## Decision

**Patch (0.9.8), not minor.** The `{:notification, map}` a screen receives
keeps every key it had (`id`, `title`, `body`, `source`, `data`) and gains
`presentation` and `action`; code that matched the old map still matches. iOS
`data` no longer has `aps`, which was always `nil`. The one behaviour that no
longer holds: on iOS, a process registered through mob_notify in an app that
never calls `Mob.Screen.start_root` used to get notifications directly and now
gets them only through the root screen's router. That is a real behaviour
change, accepted as a limitation rather than counted as an API break: the
screen-facing API is unchanged, an app without a root screen has no UI,
every generated app starts one, and no app we know of registers without one.
The CHANGELOG states the limitation so such an app can add a root screen.

**A named face keeps its weight under `font_weight: "regular"`.** MOB-237
stopped `resolvedFont` from applying `.weight(.regular)` to every named face,
which drew the documented `heading: "Inter-Bold"` at regular weight. iOS
cannot tell an explicit `"regular"` from the default (`MobNode` initialises
`fontWeight` to `"regular"`), so `font: "Inter-Bold", font_weight: "regular"`
now draws bold where 0.9.7 drew it regular. Android loads a named font as a
single-face `FontFamily`, where a lighter requested weight still draws that
face, so the new iOS behaviour is the cross-platform one. Asking a bold face
for regular weight is contradictory; name the regular face. The CHANGELOG
entry says so.

## Consequences

- If a real app turns out to rely on iOS delivery without a root screen, the
  fix is in mob (deliver to the registered pid when no router is up), not a
  version renumbering.
- Distinguishing an explicit `font_weight: "regular"` would need `MobNode` to
  track whether the prop was set, on both the SwiftUI and UIKit text paths.
  Not worth it while Android behaves the same way.
